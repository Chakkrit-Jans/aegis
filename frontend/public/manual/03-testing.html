พิสูจน์: เปิด Auto-approve แล้วตั้ง objective ที่มีเป้าใน scope + นอก scope ปนกัน — ตัวในจะรัน ตัวนอกจะถูกบล็อกอัตโนมัติ Prove it: enable Auto-approve with an objective mixing in-scope and out-of-scope targets — in-scope runs, out-of-scope is auto-blocked.

⚠ ความจริงที่ต้องเข้าใจThe honest realityเครื่องมืออัตโนมัติ (http_probe, nmap, dir_enum, web_vuln_scan/nuclei, run_command) เก่งเรื่องผิวเผินและ endpoint จริง — header ที่ขาด, ไดเรกทอรีเปิด, เวอร์ชันล้าสมัย, และช่องโหว่ที่ยิงยืนยันได้ตรง ๆ (เช่น SQLi ที่ Juice Shop) · แต่บทเรียน WebGoat ส่วนใหญ่ต้อง login + ทำเป็นขั้นตอน (IDOR, stored XSS, XXE, CSRF, SSRF, JWT) — พวกนี้ทำมือผ่านแท็บ Desktop ระบบจะไม่เจอเองAutomated tools (http_probe, nmap, dir_enum, web_vuln_scan/nuclei, run_command) excel at surface + real endpoints — missing headers, exposed directories, outdated versions, and directly-verifiable flaws (e.g. SQLi on Juice Shop). But most WebGoat lessons are authenticated, multi-step (IDOR, stored XSS, XXE, CSRF, SSRF, JWT) — those are done by hand via the Desktop tab; the scanner won't find them on its own.

ตัวอย่างจริง: Injection (A03) — จากโจทย์ถึงรายงานWorked example: Injection (A03) — objective to report

โจทย์นี้สั่งให้ ยืนยัน ช่องโหว่ (ไม่ใช่แค่สแกนผ่าน ๆ) — เคล็ดลับคือระบุให้ใช้ run_command ยิงจริงและบอกว่า “อะไรคือหลักฐานที่พิสูจน์ได้”:This objective tells the agent to confirm the flaw (not just scan) — the trick is to name run_command and state “what proves it”:

Validate two issues on juiceshop:3000 using run_command, then report.
(1) SQL injection auth bypass at POST /rest/user/login — email = ' OR 1=1--
    password = x. If the JSON response contains an authentication token,
    it is CONFIRMED (critical, certain).
(2) Exposed directory /ftp/ — if GET returns HTTP 200 it is exposed
    (medium, certain). Also record missing CSP/HSTS (low).
save_finding (description, impact, remediation, confidence) each, then
generate_report.
