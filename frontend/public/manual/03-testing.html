ทดสอบ Aegis กับ WebGoat & Juice ShopTesting Aegis on WebGoat & Juice Shop

คู่มือเชิงปฏิบัติ: ใช้ Aegis เดินงานจริงกับเป้าหมายฝึกทั้งสอง ทีละสถานการณ์ พร้อมข้อความ objective ที่ก็อปไปใช้ได้เลย และผลลัพธ์ที่ควรเห็นA hands-on playbook: drive Aegis against both practice targets, scenario by scenario, with copy-paste objectives and the results you should expect.

⚠ ขอบเขตScopeทำเฉพาะกับ WebGoat/Juice Shop ที่คุณรันเองเท่านั้น ทุกขั้นตอนในคู่มือนี้ถือว่าเป็นแล็บที่ได้รับอนุญาตDo this only against WebGoat/Juice Shop you run yourself. Every step here assumes an authorized lab.

1. สิ่งที่ต้องมีก่อนPrerequisites

  1. เป้าหมายรันอยู่และ worker ยิงถึง — ทำตาม Book 02 หัวข้อ 7–8 (curl เห็น 200)Targets are running and reachable from the worker — follow Book 02 §7–8 (curl returns 200).
  2. AI Provider มีตัว default และกด Test ผ่านแล้ว (Book 01 §5)AI Provider has a default set and passes Test (Book 01 §5).
  3. Worker กด Health แล้วเห็นเครื่องมือครบ (Book 01 §6)Worker Health check shows the full toolset (Book 01 §6).

  1. + New — ชื่อ juice-lab, client internal lab+ New — name juice-lab, client internal lab.
  2. Record authorization — Authorized by me, ref self-hosted labRecord authorization — Authorized by me, ref self-hosted lab.
  3. + in-scope — ใส่ host.docker.internal (หรือชื่อคอนเทนเนอร์ถ้าใช้วิธี B)+ in-scope — add host.docker.internal (or the container name if you used Option B).

3. สถานการณ์ A — Recon + Web Vuln Scan (Juice Shop)Scenario A — Recon + Web Vuln Scan (Juice Shop)

ให้ AI ทำ recon แล้วสแกนช่องโหว่เว็บ — ครอบคลุมเฟส RECON และ VULN SCANHave the AI recon then scan the web app — this covers the RECON and VULN SCAN phases.

วาง objective นี้:Paste this objective:

Assess the web application at host.docker.internal:3000 (OWASP Juice Shop,
authorized lab). Do passive recon (dns, http probe, whatweb), map open ports
and services, then run a web vulnerability scan. For every issue call
save_finding with evidence, business impact, a risk rating and a concrete
remediation, then call generate_report.
  1. กด ▶ Spawn session — แผงขวาเริ่มสตรีมว่า AI อยู่เฟสไหนPress ▶ Spawn session — the right panel streams which phase the AI is in.
  2. เมื่อถึง nmap_scan / web_vuln_scan จะมีการ์ดอนุมัติเหลือง — อ่านเหตุผล + คำสั่ง แล้วกด APPROVEOn nmap_scan / web_vuln_scan a yellow approval card appears — read the rationale and command, then APPROVE.
  3. passive tool (http_probe, whatweb) จะรันเองโดยไม่ขออนุมัติPassive tools (http_probe, whatweb) run without asking.

4. สถานการณ์ B — Directory EnumerationScenario B — Directory Enumeration

หาเส้นทางที่ซ่อนอยู่ เช่น /ftp/ (เอกสารลับ) และ /#/administration (หน้า admin) ของ Juice ShopDiscover hidden paths such as /ftp/ (confidential docs) and /#/administration (admin page) on Juice Shop.

On host.docker.internal:3000 enumerate directories and hidden endpoints
with a common wordlist. Flag anything sensitive (backups, /ftp, admin,
config, api). Save findings with the exact URLs and remediation, then report.

tool dir_enum (ffuf/gobuster) เป็น active → ต้องอนุมัติ · ผลลัพธ์ที่ควรเห็นคือ /ftp/ ตอบ 200The dir_enum tool (ffuf/gobuster) is active → needs approval · you should see /ftp/ returning 200.

5. สถานการณ์ C — SQL Injection ที่หน้า LoginScenario C — SQL Injection at Login

challenge คลาสสิกของ Juice Shop: ล็อกอินเป็น admin ด้วย SQLi ที่ช่อง email (' OR true--) ที่นี่ให้ Aegis ยืนยันว่าช่องโหว่มีจริงด้วย run_command (intrusive) Juice Shop's classic challenge: log in as admin via SQLi in the email field (' OR true--). Here Aegis validates the flaw with run_command (intrusive).

Check the login endpoint of host.docker.internal:3000 for SQL injection.
Craft a single safe proof-of-concept request that demonstrates auth bypass
(do NOT alter data). If confirmed, save_finding with the request/response
evidence, impact (admin auth bypass), risk = High, and remediation
(parameterized queries), then generate_report.
  1. tool run_command เป็น intrusive — Aegis จะโชว์คำสั่ง curl จริงในการ์ด ก่อนกด APPROVE อ่านให้แน่ใจว่าอยู่ในขอบเขตและไม่ทำลายข้อมูลThe run_command tool is intrusive — Aegis shows the exact curl in the card. Before APPROVE, confirm it stays in scope and is non-destructive.
  2. ตัวอย่างคำสั่งที่ AI อาจเสนอ:Example command the AI may propose: 
    curl -s -X POST http://host.docker.internal:3000/rest/user/login \
  -H "Content-Type: application/json" \
  -d '{"email":"'"'"' OR true--","password":"x"}'
  3. ถ้าตอบกลับมี authentication token = ยืนยัน auth bypass → AI บันทึกเป็น finding ระดับ HighIf the response returns an authentication token = auth bypass confirmed → the AI records a High-severity finding.
นี่คือจุดสำคัญของ AegisThis is the point of Aegisคุณเห็นคำสั่งที่จะยิงก่อนมันรันจริง และตัดสินใจเอง — นี่คือ human-in-the-loopYou see the exact command before it runs and decide yourself — that is the human-in-the-loop.

6. สถานการณ์ D — WebGoat (บทเรียนเจาะจง)Scenario D — WebGoat (targeted lessons)

WebGoat ต้องล็อกอิน/มี session ก่อนถึงบทเรียน ดังนั้นการสแกนอัตโนมัติจะเห็นแค่หน้า login เป็นหลัก ใช้ Aegis สำหรับ recon + ตรวจ header/CVE ของตัวแอป และใช้แท็บ Terminal/Desktop ทำบทเรียนที่ต้องมี session เอง WebGoat requires a login/session before its lessons, so automated scanning mostly sees the login page. Use Aegis for recon + checking the app's headers/CVEs, and use the Terminal/Desktop tabs for session-based lessons.

Recon host.docker.internal:8080 (OWASP WebGoat, authorized lab): identify
the server/framework and version, check security headers (HSTS, CSP,
X-Frame-Options), and search for known CVEs of the detected components.
Save findings with remediation, then generate_report.
💡 เคล็ดลับTipบทเรียน WebGoat แบบ SQLi/JWT/Access-Control เหมาะทำมือผ่านแท็บ Desktop (Firefox + Burp บน Kali) มากกว่าให้ AI ยิงอัตโนมัติWebGoat's SQLi/JWT/Access-Control lessons are better done by hand via the Desktop tab (Firefox + Burp on Kali) than by fully automated scanning.

7. Auto-approve ในแล็บAuto-approve in the lab

เมื่อมั่นใจว่าเป้าหมายคือแล็บของตัวเอง ติ๊ก Auto-approve ตอน spawn เพื่อให้ AI เดินครบทุกเฟสโดยไม่ต้องกดอนุมัติทีละครั้ง — Scope gate ยังกันเป้านอกขอบเขตอยู่ Once you're sure the target is your own lab, tick Auto-approve when spawning so the AI runs every phase without per-step approval — the scope gate still blocks anything out of scope.

พิสูจน์: เปิด Auto-approve แล้วตั้ง objective ที่มีเป้าใน scope + นอก scope ปนกัน — ตัวในจะรัน ตัวนอกจะถูกบล็อกอัตโนมัติ Prove it: enable Auto-approve with an objective mixing in-scope and out-of-scope targets — in-scope runs, out-of-scope is auto-blocked.

8. รายงาน + Export PDFReport + Export PDF

  1. เมื่อ session จบ แผงซ้ายโชว์ Findings — กด 📄 View report เพื่อดูรายงานเต็มWhen the session ends, the left panel lists Findings — click 📄 View report for the full report.
  2. รายงานมี Scan statistics + ตาราง Issues found (จัดกลุ่มตามชนิด พร้อมคอลัมน์ Severity/Confidence) แล้วตามด้วย Findings & Remediation ที่แต่ละใบแยกหัวข้อ Description · Impact/Risk · Remediation ชัดเจนThe report has Scan statistics + an Issues found table (grouped by type, with Severity/Confidence columns), then Findings & Remediation cards split into clear Description · Impact/Risk · Remediation sections.
  3. กด ⬇ Export PDF — เปิดหน้า preview แล้วกด 🖨️ Print / Save as PDFClick ⬇ Export PDF — a preview opens; click 🖨️ Print / Save as PDF.
  4. เปิดแท็บ Dashboard เพื่อดู finding/session ที่รันไป รวมทุกงาน — โดนัท severity/confidence และ session status จะขยับตามผลที่เพิ่ง save · เปิด session เก่าได้จาก Session historyOpen the Dashboard tab to see findings/sessions roll up across all runs — the severity/confidence and session-status donuts move as new results are saved · re-open past runs from Session history.
