คู่มือการใช้งาน AegisAegis User Guide

แพลตฟอร์มสั่งการทดสอบเจาะระบบด้วย AI ที่มี “คนอนุมัติทุกขั้นตอน” — ตั้งค่าครั้งเดียว แล้วเดินงานได้ตั้งแต่ต้นจนออกรายงานให้ลูกค้าAn AI-driven penetration-testing console with a human in the loop on every intrusive action — configure once, then run an engagement from scope to a client-ready report.

1. Aegis คืออะไรWhat is Aegis

Aegis เป็นระบบที่ให้ AI ทำหน้าที่ “ผู้ทดสอบเจาะระบบ” — มันวางแผน เลือกเครื่องมือ และวิเคราะห์ผลเอง แต่ทุกคำสั่งที่เป็น active/intrusive จะต้องหยุดรอให้คุณกดอนุมัติก่อน และถูกจำกัดด้วยขอบเขต (scope) ที่คุณกำหนด งานจบลงด้วยรายงานพร้อมหลักฐาน ผลกระทบ และวิธีแก้ Aegis lets an AI act as the penetration tester — it plans, picks tools, and analyzes results on its own, but every active / intrusive command pauses for your approval and is confined to the scope you set. An engagement ends with a report containing evidence, impact, and remediation.

🧠 AI ขับเคลื่อนAI-driven

วางแผนเป็นเฟส: recon → สแกน → ทดสอบ credential → ยืนยันช่องโหว่ → รายงานPlans in phases: recon → scan → credential testing → validation → reporting.

🚦 มีประตูกั้นGated

Scope Gate + Approval Gate กันการยิงนอกขอบเขตและกันการทำงานโดยไม่ได้รับอนุญาตA Scope Gate and Approval Gate stop out-of-scope or unapproved actions.

🧾 ตรวจสอบย้อนหลังได้Auditable

ทุกการอนุมัติ/คำสั่ง/การลบ ถูกบันทึกใน Audit LogEvery approval, command, and deletion is written to the Audit Log.

🛠️ เครื่องมือจริงReal tools

รันบนเครื่อง Kali จริง: nmap, nuclei, ffuf, hydra, ฯลฯRuns real Kali tooling: nmap, nuclei, ffuf, hydra, and more.

2. สถาปัตยกรรมArchitecture

ระบบแยกเป็นส่วน ๆ ผ่าน Docker: หน้าเว็บ (Next.js) → หลังบ้าน (Node/Express + Socket.IO) → เครื่อง Kali worker ที่รันเครื่องมือจริง โดยมี MongoDB/Redis เก็บสถานะ The system is split into Docker services: a Next.js web console → a Node/Express + Socket.IO backend → one or more Kali workers that run the real tools, with MongoDB/Redis holding state.

3. แนวคิดความปลอดภัย 4 อย่างFour safety concepts

① Scope Gate

ก่อนยิงเครื่องมือที่ระบุเป้าหมาย ระบบเช็คว่าเป้าอยู่ใน include และไม่อยู่ใน exclude — ถ้านอกขอบเขตจะถูกบล็อกทันที แม้ AI อยากทำก็ตาม Before any tool that names a target runs, Aegis checks the target is in include and not in exclude — out-of-scope targets are blocked immediately, even if the AI wants to proceed.

② Approval Gate

เครื่องมือทุกตัวที่เป็น active หรือ intrusive จะหยุดรอการ์ดอนุมัติ — คุณเห็นเหตุผลของ AI + คำสั่งจริง แล้วกด APPROVE / REJECT Every active or intrusive tool pauses on an approval card — you see the AI's rationale and the exact command, then APPROVE / REJECT.

③ Auto-approve

โหมดเสริม (checkbox ตอน spawn) ที่ปิดเฉพาะ “การอนุมัติของคน” เพื่อให้เดินเร็วในแล็บ — Scope Gate ยังทำงานอยู่เสมอ An opt-in mode (a checkbox when you spawn) that skips only the human approval so lab runs go faster — the Scope Gate still applies at all times.

⚠ ระวังCautionใช้ Auto-approve เฉพาะเป้าหมายที่คุณเป็นเจ้าของ/แล็บของตัวเองเท่านั้นOnly enable Auto-approve on lab targets you own or are explicitly authorized to hammer.

④ Audit + RBAC

ผู้ใช้มีบทบาท admin/operator; ทุกเหตุการณ์สำคัญถูกบันทึกถาวรและดูได้ที่ Settings → Audit Log Users are admin or operator; every significant event is recorded permanently and viewable in Settings → Audit Log.

7. ตั้งค่า Kali WorkersKali Workers

worker คือคอนเทนเนอร์ Kali ที่รันเครื่องมือจริง (nmap, nuclei, ffuf, hydra …) ผ่าน exec-agent ที่กั้นด้วย token — เป็นส่วนเดียวที่แตะเป้าหมายจริง มีได้หลายตัวเพื่อแยกงานตามลูกค้า/เครือข่าย แต่ละ engagement เลือก worker ของตัวเองได้ หรือใช้ตัว default A worker is a Kali container that runs the real tools (nmap, nuclei, ffuf, hydra …) via a token-gated exec-agent — the only component that touches the target. Register several to isolate work per client / network; each engagement can pick its own worker or use the default.

เพิ่ม worker (Settings → Kali Workers)Add a worker (Settings → Kali Workers)

  1. กด + Add worker แล้วกรอก 3 ช่อง: Name (เช่น Kali · client-A), URL (internal exec-agent) (เช่น http://worker2:7000) และ Token (ค่าเดียวกับ WORKER_TOKEN)Click + Add worker and fill three fields: Name (e.g. Kali · client-A), URL (internal exec-agent) (e.g. http://worker2:7000) and Token (the same value as WORKER_TOKEN).
  2. กด Health — ถ้าเชื่อมได้จะขึ้น OK · 12 tools (จำนวนเครื่องมือที่มี) ถ้าเชื่อมไม่ได้ขึ้น DOWN: …Click Health — a reachable worker shows OK · 12 tools (the toolset count); an unreachable one shows DOWN: …
  3. กด Set default เพื่อให้เป็น worker ปริยาย (งานที่ไม่ได้เลือก worker จะใช้ตัวนี้) · แก้ไขด้วย Edit (เว้น Token ว่างไว้ = ใช้ token เดิม) · ลบด้วย DeleteClick Set default to make it the fallback (engagements without an explicit worker use it) · Edit to change it (blank Token = keep the current one) · Delete to remove.
💡 เกร็ดNotesworker แรกชื่อ Primary Kali ถูกสร้างอัตโนมัติจาก WORKER_URL/WORKER_TOKEN ใน .env และตั้งเป็น default ให้ · URL ใช้ชื่อ service ใน docker network (เช่น worker, worker2) พอร์ต exec-agent คือ 7000 เสมอ · ถ้าลบตัวที่เป็น default ระบบจะเลื่อน default ไปที่ตัวแรกที่เหลือThe first worker Primary Kali is auto-seeded from WORKER_URL/WORKER_TOKEN in .env and made default · the URL is a docker-network service name (e.g. worker, worker2); the exec-agent port is always 7000 · deleting the default promotes the first remaining worker.
🏢 EnterpriseCommunity รันได้ 1 worker · การเพิ่มตัวที่ 2 จะถูกกั้นที่ backend จริง (ตอบ HTTP 402: “limited to 1 Kali worker”) — หลาย worker (แยกตามลูกค้า/เครือข่าย) ต้องใช้ Enterprise — ดู §18Community runs 1 worker; adding a 2nd is blocked at the backend (HTTP 402: “limited to 1 Kali worker”). Multiple workers (per-client/network isolation) needs Enterprise — see §18.

7.1 Proxy · Burp / Caido7.1 Proxy · Burp / Caido

ส่ง web tool ที่เป็น active (nuclei และ ffuf) ผ่าน proxy ดักจับ เพื่อให้เห็น/บันทึกทุก request ใน Burp หรือ Caido — เครื่องมืออื่น (nmap, hydra, http_probe) ไม่ถูก route ผ่าน proxy Route the active web tools (nuclei and ffuf) through an intercepting proxy so every request is visible/logged in Burp or Caido — other tools (nmap, hydra, http_probe) are not proxied.

  1. เลือก Type: Burp Suite / Caido / CustomPick a Type: Burp Suite / Caido / Custom.
  2. ใส่ Proxy URL — จากใน worker container เข้าถึง proxy บนเครื่อง host ด้วย http://host.docker.internal:8080 (Burp) หรือ :8081 (Caido)Enter the Proxy URL — from inside the worker container reach the host's proxy via http://host.docker.internal:8080 (Burp) or :8081 (Caido).
  3. กด Enable & save · แถบ Status จะขึ้น ON → … — ปิดด้วย Disable (OFF)Click Enable & save · the Status line shows ON → … — turn it off with Disable (OFF).
⚠ เข้าถึง hostReaching the hosthost.docker.internal คือชื่อที่ container ใช้เรียกเครื่อง host — ต้องเปิด Burp/Caido ให้ listen ที่ 0.0.0.0 (หรือ all interfaces) ไม่ใช่แค่ 127.0.0.1 ไม่งั้น worker จะต่อไม่ติดhost.docker.internal is how a container addresses the host — set Burp/Caido to listen on 0.0.0.0 (all interfaces), not just 127.0.0.1, or the worker can't connect.

  1. สร้าง bot กับ @BotFather ใน Telegram → ได้ Bot token (รูปแบบ 123456:ABC-…)Create a bot with @BotFather in Telegram → you get a Bot token (looks like 123456:ABC-…).
  2. หา Chat id ของคุณ (เช่น ทักบอท @userinfobot จะบอกเลข id) — ใส่เป็นตัวเลข เช่น 123456789Find your Chat id (e.g. message @userinfobot which replies with your numeric id) — enter it like 123456789.
  3. วาง Bot token + Chat id → Enable & save → กด Send test ควรได้ข้อความ “✅ Aegis Telegram gateway connected.” ในแชทPaste the Bot token + Chat id → Enable & save → click Send test; you should receive “✅ Aegis Telegram gateway connected.” in the chat.
💡 เกร็ดNoteทุกการกดปุ่มบน Telegram ถูกบันทึกใน Audit Log ด้วย (actor = telegram:@username) เหมือนกดในหน้าเว็บ — ยังอยู่ในกรอบ approval + scope เดิมทุกอย่างEvery Telegram button press is written to the Audit Log too (actor = telegram:@username), exactly like clicking in the web UI — the same approval + scope rules still apply.

14. รายงาน (Report)The Report

เมื่อ AI บันทึก finding แล้ว Aegis จะรวมเป็นรายงานพร้อมส่งลูกค้า — เป็นหน้า HTML พิมพ์เป็น PDF ได้ในคลิกเดียว รายงานผสม 2 สไตล์เข้าด้วยกัน: ส่วนสรุปแบบสแกนเนอร์ (เหมือน Burp Suite — สถิติ + ตารางรวมช่องโหว่) และส่วนเล่าเรื่องเชิงที่ปรึกษา (แต่ละ finding มีหลักฐาน ผลกระทบ และวิธีแก้) Once the agent has saved findings, Aegis composes a client-ready report — an HTML page you print to PDF in one click. It blends two styles: a scanner-style summary (like Burp Suite — statistics + a rolled-up issues table) and a consultant-style narrative (each finding with evidence, impact and a fix).

โครงของรายงานWhat the report contains

  1. หน้าปก — ชื่องาน, ลูกค้า, วันที่, Overall risk (แถบสีตาม severity สูงสุด) และ scope ที่ทดสอบCover — engagement name, client, date, an Overall risk band (coloured by the highest severity) and the tested scope.
  2. Executive Summary — ย่อหน้าอธิบาย + สองตารางคู่กัน: Issues by severity (นับ Critical→Info) และ Scan statistics (จำนวน issue รวม, asset ที่ได้รับผลกระทบ, severity สูงสุด, และแยกตาม Confidence Certain/Firm/Tentative)Executive Summary — a paragraph plus two side-by-side tables: Issues by severity (Critical→Info counts) and Scan statistics (total issues, unique affected assets, highest severity, and a Confidence breakdown — Certain/Firm/Tentative).
  3. Issues found on <scope> ใหม่ — ตารางรวมแบบ Burp: จัดกลุ่ม finding ตามชนิด (แต่ละชนิดบอกจำนวน instance) แล้วแตกเป็นแถวละ 1 asset พร้อมคอลัมน์ Severity และ Confidence — เห็นภาพรวมทุก URL ที่โดนในพริบตาIssues found on <scope> new — a Burp-style roll-up: findings grouped by type (each shows an instance count), one row per affected asset with Severity and Confidence columns — every hit URL at a glance.
  4. Findings & Remediation — การ์ดเรียงตาม severity แต่ละใบมีป้ายระดับ, Confidence, asset ที่กระทบ และแบ่งเป็น 3 หัวข้อชัดเจน: Description (สรุปปัญหา + หลักฐาน), Impact / Risk (ความเสี่ยง — สีตามระดับ), Remediation (แนวทางป้องกัน — สีเขียว) และ Evidence/Notes ถ้ามีFindings & Remediation — cards ordered by severity, each with a severity badge, Confidence, affected asset, and three clear sections: Description (the problem + evidence), Impact / Risk (tinted by severity), Remediation (in green), plus Evidence/Notes when present.

Confidence (ระดับความมั่นใจ)Confidence

ทุก finding มีค่า Confidence ที่ AI กำหนดให้ เพื่อบอกว่ายืนยันได้แน่แค่ไหน — ช่วยให้ลูกค้าจัดลำดับความสำคัญได้ (ต่างจาก severity ที่บอก “รุนแรงแค่ไหน”) Every finding carries a Confidence the agent assigns, telling the reader how sure the issue is real — orthogonal to severity (which is “how bad”).

ConfidenceความหมายMeaning
Certainพิสูจน์/exploit ได้จริงแล้ว — มีหลักฐานชัดProven / exploited — hard evidence.
Firmหลักฐานหนักแน่นแต่ยังไม่ได้ยิงพิสูจน์เต็มที่Strong evidence, not fully exploited.
Tentativeสงสัย/บ่งชี้ ควรตรวจซ้ำด้วยมือSuspected / indicative — verify manually.
💡 การจัดกลุ่มGroupingช่องโหว่ชนิดเดียวกันที่พบบนหลาย asset จะถูกรวมเป็นกลุ่มเดียวในตาราง “Issues found” เมื่อ AI ใช้ title เดียวกัน — ดังนั้นถ้าบันทึกเองหรือปรับ prompt ให้ตั้งชื่อ finding ชนิดเดียวกันให้ตรงกัน จะได้รายงานที่รวบรัดสวยงามThe same issue type seen on multiple assets rolls into one group in “Issues found” when the agent reuses the same title — so keeping titles consistent for the same class of issue yields a tidy report.

  2. กรอก Issuer URL (เช่น https://accounts.google.com), Client ID, Client secret, และ Button label (ข้อความบนปุ่มหน้า login)Fill Issuer URL (e.g. https://accounts.google.com), Client ID, Client secret, and a Button label (the text on the login button).
  3. (ไม่บังคับ) จำกัด Allowed email domains (คั่นด้วย comma, เว้นว่าง = ทุกโดเมน) · เลือก New-user role (operator/admin) · ติ๊ก Auto-provision new users on first SSO loginOptionally restrict Allowed email domains (comma-separated, blank = any) · choose the New-user role (operator/admin) · tick Auto-provision new users on first SSO login.
  4. ติ๊ก Enable SSO sign-in button → Save SSO settings · หน้า login จะมีปุ่ม “🔑 <label>” เหนือช่อง email/passwordTick Enable SSO sign-in button → Save SSO settings · the login page now shows a “🔑 <label>” button above the email/password form.
🔐 ความปลอดภัยSecurityตรวจ ID token ด้วย RS256 (audience = Client ID, issuer ตรง, nonce ตรง) · state/nonce เก็บใน Redis ใช้ครั้งเดียว หมดอายุ 10 นาที · ถ้าปิด auto-provision และไม่มีบัญชีอยู่ก่อน จะล็อกอินไม่ได้ (“no Aegis account for …”)ID tokens are verified RS256 (audience = Client ID, issuer & nonce matched) · state/nonce are one-time, stored in Redis, expire in 10 min · with auto-provision off and no pre-existing account, login is refused (“no Aegis account for …”).

18.4 · 📚 Org Template LibraryOrg Template Library

คลังเทมเพลตกลางขององค์กรที่ admin ดูแล และ operator ทุกคนเห็นใน objective picker (ต่างจาก Custom Template ใน §11 ที่เป็นของส่วนตัวใครของมัน) · export/import เซ็นดิจิทัลด้วย Ed25519 ป้องกันการแก้ไข · ตั้งที่ Settings → Org Template Library A team-shared, admin-curated library every operator sees in the objective picker (unlike the personal Custom Templates in §11) · export/import is Ed25519-signed against tampering · configure in Settings → Org Template Library.

  1. เพิ่มเข้าคลัง — ช่อง Add a template: ใส่ Template name + คำสั่งของแต่ละระดับ (Basic/Medium/Advanced, ใช้ <TARGET>) → Add to library (ต้องมีอย่างน้อย 1 ระดับ)Add to library — the Add a template form: a Template name + a command per level (Basic/Medium/Advanced, use <TARGET>) → Add to library (at least one level required).
  2. แชร์แบบเซ็น — ⬇ Export signed bundle ได้ไฟล์ aegis-org-templates.signed.json (มี public key + ลายเซ็น) · อีกเครื่องกด ⬆ Import signed bundle เพื่อโหลด (import จะแทนที่คลังทั้งหมด)Signed sharing — ⬇ Export signed bundle gives aegis-org-templates.signed.json (with a public key + signature) · another instance uses ⬆ Import signed bundle to load it (import replaces the whole library).
  3. import สำเร็จจะขึ้น “✅ Imported n templates · verified signer <fingerprint>” · ถ้าไฟล์ถูกแก้ จะถูกปฏิเสธ (“signature verification failed — bundle was tampered with”)A good import shows “✅ Imported n templates · verified signer <fingerprint>” · a tampered file is rejected (“signature verification failed — bundle was tampered with”).
🔏 ลายเซ็นทำงานอย่างไรHow signing worksแต่ละ instance มีคู่กุญแจ Ed25519 ของตัวเอง (สร้างอัตโนมัติครั้งแรก, private key ไม่เคยออกจาก server) · bundle พก public key + fingerprint + ลายเซ็นที่ครอบเฉพาะ name+levels — แก้เนื้อในแม้นิดเดียว ลายเซ็นก็ไม่ผ่านEach instance has its own Ed25519 keypair (auto-generated on first use; the private key never leaves the server) · a bundle carries the public key + fingerprint + a signature over name+levels — change any content and verification fails.
